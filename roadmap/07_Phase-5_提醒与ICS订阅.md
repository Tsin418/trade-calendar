# 07｜Phase 5：提醒与 ICS 订阅

## 1. 阶段目标

实现可靠、可配置、不会重复的提醒系统，并提供稳定 UID 的私有 ICS 日历订阅。

建议周期：1 周。

## 2. 进入条件

- Phase 4 的事件变更识别稳定；
- 事件版本和来源优先级已经验证；
- 飞书 Webhook 和提醒时间已配置；
- 用户时区规则已确认。

## 3. 我要完成的事情

### 3.1 提醒规则

- [ ] 每日摘要；
- [ ] 晚间预览；
- [ ] Critical 提前 120、60、15 分钟；
- [ ] High 提前 60、15 分钟；
- [ ] Medium 提前 30 分钟；
- [ ] Low 默认不提醒；
- [ ] 用户可以覆盖默认提前量；
- [ ] 单事件提醒开关；
- [ ] 国家、市场和类别过滤。

### 3.2 变更和异常提醒

- [ ] 新增 Critical 或 High；
- [ ] 事件改期；
- [ ] 事件取消；
- [ ] TBA 变为具体时间；
- [ ] 高优先级来源冲突；
- [ ] Watchlist 公司新增事件；
- [ ] 数据源连续失败；
- [ ] Worker 无心跳；
- [ ] 备份失败预留。

### 3.3 通知队列和去重

- [ ] 生成计划通知；
- [ ] 使用 `channel + event + alert_type + schedule + version` 唯一键；
- [ ] 相同版本相同节点只发送一次；
- [ ] 事件改期后取消旧计划通知；
- [ ] 发送成功、失败和重试状态；
- [ ] 1、5、15 分钟重试；
- [ ] 连续失败形成系统告警；
- [ ] 手工测试通知。

### 3.4 飞书消息

- [ ] 消息标题区分新增、改期、提醒和异常；
- [ ] 显示中文标题和原始机构；
- [ ] 显示用户时间、原始时区和倒计时；
- [ ] 显示重要性、确认状态和影响市场；
- [ ] 显示官方来源；
- [ ] 显示最后核验时间；
- [ ] 消息内提供事件详情链接。

### 3.5 ICS 订阅

- [ ] 私有 Token；
- [ ] 稳定 UID；
- [ ] 事件改期更新原 ICS 事件；
- [ ] 取消事件正确输出状态；
- [ ] TBA 和仅日期事件正确输出；
- [ ] 用户时区或标准时区处理；
- [ ] Token 轮换；
- [ ] Google、Apple 和 Outlook 兼容性检查。

## 4. 需要实现的目标

- 相同提醒不会重复发送；
- 改期不会同时保留错误的旧提醒；
- 通知失败可以自动恢复并可追踪；
- 日期事件不会收到错误的分钟级提醒；
- ICS 改期不会生成重复日历项；
- 私有订阅地址泄露后可以更换 Token。

## 5. 交付物

- 提醒规则管理；
- 通知调度、发送、去重和重试模块；
- 飞书消息模板；
- 通知测试接口；
- 私有 ICS Feed；
- ICS 配置和使用说明；
- 提醒和 ICS 测试。

## 6. 验收场景

- [ ] 每日摘要按用户时区执行；
- [ ] Critical 事件生成正确的三个提醒节点；
- [ ] 相同 Worker 任务执行两次只发送一次；
- [ ] 改期后旧提醒被取消，新提醒被创建；
- [ ] 飞书失败后按顺序重试；
- [ ] TBA 事件不产生具体分钟提醒；
- [ ] ICS 同一事件改期后 UID 不变；
- [ ] 取消事件在 ICS 中被正确更新；
- [ ] Token 轮换后旧地址失效。

## 7. 主要风险

- Worker 时区配置导致提醒偏移；
- 改期与通知调度同时发生形成竞态；
- 飞书限流或临时不可用；
- ICS 客户端刷新存在延迟；
- Token 被日志或页面意外泄露。
