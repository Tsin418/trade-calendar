# 05｜Phase 3：日历界面与交互

## 1. 阶段目标

把事件核心能力变成可以每天使用的交易日历界面。优先保证高影响事件可见、状态清晰、时间准确和高密度信息可读。

建议周期：2 周。

- Phase 2 已通过验收；
- 事件查询、筛选、版本和人工修改 API 可用；
- 已准备覆盖各种时间精度和状态的演示数据。

## 4. 需要实现的目标

- 打开首页后一个屏幕内找到下一个高影响事件；
- 状态不能只依赖颜色表达；
- 月历在高事件密度下仍然可读；
- 日期、时间和倒计时不会互相矛盾；
- 用户能在不离开当前页面的情况下查看和修改事件；
- 来源失败不能被展示成“当天没有事件”。

## 7. 主要风险

- FullCalendar 的定制行为与状态模型冲突；
- 月历信息过多导致不可读；
- 倒计时频繁刷新造成性能问题；
- 移动端 Drawer 和日历交互复杂；
- 过早追求视觉细节影响业务闭环。
