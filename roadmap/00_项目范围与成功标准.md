# 00｜项目范围与成功标准

## 1. 产品目标

建设一个单用户、自用的动态交易事件日历，使用户能够快速判断：

- 今天、明天、本周和本月有哪些重要事件；
- 下一个高影响事件何时发生；
- 最近有哪些新增、改期、取消或时间补充；
- 哪些事件可能影响日本、韩国、台湾、香港及全球主要风险资产；
- 哪些数据源已经延迟、失效或解析异常。

系统不承诺发现尚未公开的信息。系统承诺最大化覆盖已经公开的信息，并做到来源可追溯、变更可发现、失败不静默。

## 2. 用户与运行边界

- 用户：唯一管理员；
- 默认语言：中文，保留原始标题；
- 默认时区：待确认，系统必须支持切换；
- 运行方式：长期在线的私有网页；
- 部署方式：Docker Compose；
- 主要提醒渠道：飞书 Webhook；
- 数据来源：优先官方 API、RSS、ICS、HTML 和 PDF。

## 3. 优先级范围

### P0：MVP 必须完成

- Dashboard、Today、Tomorrow、Week、Month；
- 事件详情、搜索、筛选和个人备注；
- 人工新增、修改、忽略和字段锁定；
- 事件来源、版本、变更记录；
- 时区转换、确认状态和时间精度；
- 央行会议与核心宏观数据；
- 去重、改期、取消和时间补充识别；
- 飞书摘要、事件前提醒和异常告警；
- 数据源健康状态；
- 私有 ICS 订阅；
- 登录、HTTPS、备份和恢复。

### P1：V1.1 完成

- 官方 RSS 和网页变化监控；
- 重点公司 IR 页面；
- 临时政策关键词发现；
- 原始页面快照查看；
- 人工审核队列；
- 低置信度事件处理；
- 来源冲突管理。

### P2：V1.2 完成

- 交易所特殊交易时间；
- 股指期货最后交易日、结算日和移仓；
- 指数调整和再平衡；
- 公司财报 Watchlist；
- Actual、Consensus、Previous；
- 影响市场和重要性评分增强；
- 事件结果摘要。

## 4. 明确不做

MVP 不包含：

- 公众注册、多租户和付费订阅；
- 自动交易或下单；
- 确定性的行情涨跌预测；
- 大规模新闻聚合；
- 全世界所有市场和公司；
- 复杂微服务、Redis 或 Celery；
- 暗色模式和 PWA；
- 未经证据约束的 AI 自动发布。

## 5. 首版业务成功指标

| 指标 | 目标 |
|---|---:|
| 核心事件来源覆盖 | 每类至少 1 个主来源 |
| 关键事件备用来源 | 尽量至少 1 个 |
| 重复提醒 | 0 次 |
| 来源缺失的正式事件 | 0 条 |
| 伪造具体时间的日期事件 | 0 条 |
| 事件改期历史保留率 | 100% |
| 连续 3 次抓取失败后的告警 | 5 分钟内产生 |
| Worker 停止告警 | 5 分钟内产生 |
| 首页首屏加载 | 小于 2 秒 |
| 未来一年事件查询 | 小于 500ms |
| 备份恢复演练 | 至少成功 1 次 |
| 上线稳定性观察 | 连续 30 天 |

## 7. 范围变更规则

- 新需求必须标注为 P0、P1 或 P2；
- 增加 P0 功能必须同时说明对工期和测试范围的影响；
- 未完成的非阻断功能不能阻止核心阶段上线，但必须进入问题清单；
- 数据源覆盖范围扩大前，现有来源必须先通过稳定性检查。
