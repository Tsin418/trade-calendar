# 10｜V1.1：动态发现与审核队列

## 1. 版本目标

在 MVP 稳定运行后，增加对没有稳定结构化日历的官方网页、公司 IR 和临时政策公告的发现能力，同时用人工审核队列控制错误事件进入正式日历的风险。

建议周期：4～6 周。

## 2. 进入条件

- MVP 已完成 30 天稳定性观察；
- 核心来源、变更识别和提醒系统稳定；
- 原始快照、审核状态和来源冲突模型可用；
- 已明确新增来源的访问条款。

## 3. 我要完成的事情

### 3.1 官方 RSS 和变化发现

- [ ] 接入新增官方 RSS；
- [ ] 接入网页变化检测服务；
- [ ] 页面变化只触发重新抓取，不直接创建事件；
- [ ] 对正文区域做内容 Hash，减少无意义变化；
- [ ] 区分页面模板变化与业务内容变化；
- [ ] 为来源配置关键词和关注区域。

### 3.2 公司 IR

- [ ] 建立公司 Watchlist 管理；
- [ ] 保存 IR 日历、公告和财报入口；
- [ ] 识别财报发布日期和电话会；
- [ ] 区分正式日期、预告日期和第三方推测；
- [ ] 公司 ticker、交易所和市场标签；
- [ ] Watchlist 优先级影响抓取频率和重要性。

### 3.3 临时政策事件

- [ ] 关键词 Watchlist；
- [ ] 关注贸易、关税、产业、房地产和财政政策；
- [ ] 识别未来明确日期或时间；
- [ ] 没有明确时间的内容只进入候选队列；
- [ ] 保留证据文本和来源位置；
- [ ] 高影响候选及时通知用户审核。

### 3.4 人工审核队列

- [ ] 低置信度候选；
- [ ] 日期或时区不确定；
- [ ] 高优先级来源冲突；
- [ ] 新事件类型；
- [ ] 只有第三方来源的公司财报；
- [ ] 包含“预计”“可能”“计划”等措辞；
- [ ] 确认、修改、忽略、合并和标记 Expected；
- [ ] 审核操作形成审计记录。

### 3.5 AI 辅助，可选

- [ ] 只用于非结构化文本候选抽取；
- [ ] 使用严格 JSON Schema；
- [ ] 日期和时间必须附证据；
- [ ] 无法确定时返回 `null` 或 TBA；
- [ ] 置信度低于阈值必须人工审核；
- [ ] 不允许模型根据惯例推测日期；
- [ ] 保存模型、提示版本、输出和验证结果；
- [ ] 建立一组固定回归样本。

## 4. 需要实现的目标

- 页面变化不会自动制造错误事件；
- 低置信度候选不会直接显示为 Confirmed；
- 每个候选都能查看来源、证据和快照；
- 公司财报日期能区分官方确认和第三方预计；
- 重要临时事件可以较快进入审核队列；
- AI 停用后系统核心抓取仍能运行。

## 5. 交付物

- RSS 和网页变化接入；
- 公司 Watchlist 与 IR Adapter；
- 关键词监控；
- 人工审核页面和 API；
- 候选事件证据链；
- AI 辅助模块和回归样本，可选；
- 动态发现质量报告。

## 6. 验收标准

- [ ] 页面变化能触发重新抓取；
- [ ] 页面导航或版权变化不会频繁生成候选；
- [ ] 低置信度内容进入审核队列；
- [ ] 审核确认后正确创建或合并事件；
- [ ] 忽略候选不会反复出现；
- [ ] 证据文本可以在快照中定位；
- [ ] AI 输出缺少证据时无法通过校验；
- [ ] 动态发现不会破坏 MVP 来源稳定性。

## 7. 主要风险

- 网页变化噪声很大；
- 公司 IR 页面格式高度不统一；
- 临时事件通常没有明确时间；
- AI 抽取产生错误日期或错误分类；
- changedetection 或 RSS 路由本身可能失效；
- 动态来源数量增加后维护成本快速上升。
