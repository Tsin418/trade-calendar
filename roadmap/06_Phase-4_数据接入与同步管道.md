# 06｜Phase 4：数据接入与同步管道

## 1. 阶段目标

建立统一、可测试、可观测的数据接入管道，并接入首批核心官方来源。系统需要能够识别新增、修改、改期、取消、冲突和异常空结果。

建议周期：2～3 周。

## 2. 进入条件

- Phase 2 的事件和版本模块已通过验收；
- Phase 3 的 Sources 和 Changes 基础界面可承载结果；
- 数据源注册表、优先级和测试样本已准备；
- 已确认数据源访问条款。

## 4. 需要实现的目标

- 新增 Adapter 不需要修改核心对账流程；
- 所有来源运行均有快照、统计和错误分类；
- 同一事件多来源不会重复展示；
- 改期会更新原事件并生成版本；
- 来源异常返回 0 条不会删除历史事件；
- 人工锁定字段不会被来源覆盖；
- 重复运行同一批数据不会产生额外变化。

## 6. 验收场景

- [ ] 第一次同步创建事件；
- [ ] 第二次相同同步不产生新版本；
- [ ] 多来源同一事件只展示一次；
- [ ] 官方来源改期后生成一条改期变更；
- [ ] 日期确定、时间待定变为具体时间；
- [ ] 官方取消事件；
- [ ] 单次空结果保留旧数据并标记异常；
- [ ] HTML 结构变化产生解析错误；
- [ ] 网络失败按规则重试；
- [ ] 手动同步立即返回任务状态；
- [ ] 两个 Worker 不会同时执行同一来源。

## 7. 主要风险

- 官方页面改版；
- PDF 结构不稳定；
- 来源时间没有明确时区；
- 去重错误合并两个不同事件；
- 抓取频率违反使用条款；
- Playwright 资源消耗过高；
- 第三方来源不可长期依赖。
