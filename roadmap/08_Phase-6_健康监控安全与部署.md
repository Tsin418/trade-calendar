# 08｜Phase 6：健康监控、安全与部署

## 1. 阶段目标

让系统能够长期无人值守运行：来源失败、解析异常、Worker 停止、通知失败和备份失败都必须被发现，同时完成安全的生产部署和可验证的恢复流程。

建议周期：1 周。

## 2. 进入条件

- 核心事件、数据同步和提醒闭环已经完成；
- 生产服务器或目标环境已经准备；
- 域名、HTTPS 和访问方式已经确认；
- 数据备份目标位置已经确认。

- [ ] 连续失败次数；
- [ ] 上次成功和失败时间；

- [ ] 异常归零检测；

## 4. 需要实现的目标

- 抓取失败不能被展示为没有事件；
- Worker 停止后 5 分钟内产生告警；
- 连续 3 次来源失败后产生告警；
- 异常空结果不会删除历史数据；
- 生产环境只暴露必要端口；
- 数据库可以从最近备份恢复；
- 部署和回滚不依赖个人记忆。

## 5. 交付物

- Sources 健康管理页面；
- 系统状态接口和页面；
- 告警规则；
- 生产 Docker Compose 和 Caddyfile；
- 登录和安全配置；
- 自动备份脚本或任务；
- 恢复演练记录；
- 部署、回滚和排障文档。

## 6. 验收场景

- [ ] 模拟连续 3 次抓取失败；
- [ ] 模拟来源异常返回 0 条；
- [ ] 模拟 HTML 解析字段大量缺失；
- [ ] 停止 Worker 并验证 5 分钟内告警；
- [ ] 模拟飞书通知连续失败；
- [ ] 未登录用户不能访问后台写接口；
- [ ] 日志中没有敏感 Token；
- [ ] 外网不能直接访问数据库；
- [ ] 从备份恢复到全新数据库并完成数据抽查；
- [ ] 部署回滚流程执行成功。

## 7. 主要风险

- 监控依赖自身服务，服务完全停止时无法告警；
- 备份存在但不可恢复；
- 原始快照占满磁盘；
- Session 或反向代理配置错误；
- 自动升级依赖破坏解析器；
- 服务器内存不足以运行浏览器抓取。
